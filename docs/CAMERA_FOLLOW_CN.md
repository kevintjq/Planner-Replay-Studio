# TF 跟随与独立多视角

本次改动继续使用现有 C++ / Qt OpenGL 场景及共享录包、点云缓冲，不建立第二套渲染器。
`camera_follow.cpp` 是预览和离屏图片/视频共同使用的相机数学实现。

## 目标坐标系与时间

- Target Frame 留空使用项目当前位姿源；显式 Frame 始终优先实际 TF 链，即使其名称与当前 Odometry 的子坐标系相同，也不以另一位姿源替代。
- 只有 Odometry 的项目仍支持默认位姿跟随；加载器可用真实 Odometry 补充缺失机体边，但不能覆盖包内已有 TF。
- 其他 Frame 从录包的 `TransformTree` 查询 Fixed Frame 到目标的完整变换链，支持静态安装外参和动态 TF 插值。
- 已知 Fixed Frame 本身的目标位姿为单位变换。未知、断连、时间范围外或无有效四元数的目标不会以单位矩阵冒充成功。
- 缺少目标时，`followingTarget` 为 false，`cameraStatus` 明确报告缺少有效位姿/TF，并使用地图总览作为可见回退。
- 地图总览始终面向地图，不受目标坐标系影响。
- 跟随滞后为 0–10 秒，从当前实验时间减去设置值；不会把最新 TF 冒充过去时刻的 TF。
- 平滑为 0–10 秒的尾随实验时间窗口，均匀查询 17 个时刻。位置取均值，四元数先统一符号再归一化求均值。
  历史覆盖不足时仅使用窗口内有效样本；当前时刻必须有有效目标。计算不依赖上次渲染、播放帧率或跳转顺序。
- 默认预设保留已有相机行为；稳定 FPV 在未设置平滑时保留前后 120 毫秒方向稳定规则，并改为查询实际所选目标。

## 跟随模式

| 模式 | 行为 |
|---|---|
| Preset | 保留各相机预设原有跟随和稳定规则 |
| Position | 跟随目标位置，相机方向参考世界坐标 |
| Position + Yaw | 跟随目标位置和偏航，保持世界竖直方向 |
| Full Pose | 相机偏移和上方向随目标完整姿态旋转 |

Optical Frame 必须由用户显式开启，采用目标 Z 向前、Y 向下约定；不会根据 Frame 名称猜测。
默认使用 X 向前、Z 向上。全姿态 FPV 可以显示真实滚转；Preset 稳定 FPV 保留去滚转行为。

## 多视角与输出

附加机位内联设置包括独立目标 Frame、模式、滞后、平滑、光学约定、缩放、点大小、主点云显隐、点云和实飞轨迹颜色、场景背景及 Display 隐藏列表。
允许添加同一预设的多个机位，以配置不同目标或不同显示内容。

Display 隐藏列表是当前视角的过滤：它不能启用项目中全局关闭的 Display。
规划、目标、走廊、扫描、视场等仍遵守项目全局开关及该机位的分类开关。
该列表按真实 Display ID 保存；不会把同名 Topic 的不同 Display 合并。

背景和内容颜色属于工程/视角设置，不依赖应用亮暗主题。导出背景仍由现有画布/导出设置管理。
TF 诊断仅在编辑预览出现；`interactive=false` 或有 `captureOptions` 时不进入导出图片/视频。
预览中的地图总览回退不能作为成功的跟随机位输出。每张图片及视频每一帧在离屏请求前、
提交像素前，均从实际 CloudView 设置和该帧准确实验时间调用共享 `cameraFollowFrame`。
跟随机位的目标缺失、断连或滞后查询超出覆盖时停止输出，报告机位、实验时间和真实诊断，
不依赖异步发布的 `followingTarget`；明确选择地图总览的视角不需要目标 TF。
失败仍恢复原播放头、播放状态、画布 captureOptions 及所有已修改视角的离屏尺寸。
完整画布检查其中可见的各机位；单独视角仅检查该视角。批量导出沿用同一失败传播路径。
这些属性更新只请求现有视角重绘，不重新解析 Bag，不替换 Recording，不重新分配共享点云缓冲。
主视角与附加视角的工程字段由 `ProjectDocument` 保存。

## 验证证据与剩余验收

`native/tests/camera_follow_test.cpp` 使用真正的 Recording / TransformTree 类型构造确定性数据，检查：

- 任意目标和静态安装变换确实改变相机位置与投影矩阵。
- 实验时间滞后、平滑、随机跳转顺序的一致性。
- 未知、断连、覆盖范围外、滞后越界 TF 的明确失败状态。
- ±180° 四元数插值/平滑、三种显式跟随模式及光学轴约定。
- 地图总览目标无关、Odometry-only 默认位姿及非法参数诊断；显式 body 的 TF 与 Odometry 数值不同时以 TF 为准，缺少该链则明确失败。

`native/tests/qml/tst_camera_editor.qml` 检查实际内联组件的机位重复添加候选、全部相机字段 Apply、无效数值阻止提交、亮暗主题的 Inspector 宽度。

## 原生 RViz 场景与共享导出接线

主画布使用原生后端时，图片和视频导出现在向同一真实 RViz 场景请求指定实验纳秒时间及实际输出尺寸的
OGRE RenderTexture，再与自由画布的文字、速度表、视频等图层合成。该路径不放大原生预览图，也不会在
后端未连接、未索引、缺少必需 TF、Display 未就绪、时钟错误或输出尺寸不符时替换为旧固定话题场景。
视频各帧锁定同一场景配置版本；渲染期间视图输出尺寸改变时停止导出，避免把旧像素放大到新尺寸。

`native_scene_acceptance.cpp` 新增十项真实端到端检查：选中主视角、1080P/4K/8K 完整画布、选中图层、
两帧 MP4、实际原生 seek 期间取消、真实相机缺失目标拒绝、透明背景拒绝、恢复后的同时间像素一致性。
检查包括实际 PNG 尺寸与 DPI、标题图层像素、MP4 解码与对应帧差异、界面计时回调、精确时间及编辑状态恢复。
末尾运行截图须等待真实原生预览重新同步并进入 QML Image Ready 状态。这组新增验收仍待干净构建及实际运行，
不能以代码存在或独立后端测试替代主应用合成输出验收。

当前原生导出保持 RViz 场景自身的不透明背景，透明和不同背景覆盖明确拒绝；原生独立附加机位尚未接入，
存在可见旧附加机位时明确拒绝混合输出。上述能力以及第三方插件异步工作完成认证仍属于待完成项，
不把已接入原生主视角视为完整原生多视角或透明输出。

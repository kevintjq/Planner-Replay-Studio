# About、更新与覆盖升级发行要求

依据用户 2026-11-28 增量指令。本文件补充 v1.0.0 核心范围，不降低既有功能门禁。

## 本次必须完成

- Apple 风格 About，Light/Dark/System，真实 Logo、版本、开发者 **kevin**、工作邮箱
  `jq.tong0610@gmail.com`，邮箱可复制；GitHub、Issues、Releases、Roadmap、检查更新及完整许可证可访问。
- C++/Qt 异步 GitHub Releases 检测，启动可自动、手动可检查，更新说明、稍后提醒、跳过版本；
  不强制更新，超时/断网不影响编辑，不将历史不同产品标签当作当前稳定版本。
- 优先应用内下载安装包、进度和来源/完整性校验，经用户确认保存并退出后启动安装器。
  若当前实现/验证成本过高，可明确转后续独立 PR，保留可信 Releases 页面手动下载入口。
- Windows 同标识、同路径覆盖升级，无需先卸载。先验证新载荷，再替换旧运行文件；
  保留项目、原始素材、编辑记录及用户设置，禁止把旧 codec/插件混入新载荷。
  任意占用目录不能误认作本产品，锁定/解包失败必须保全旧安装并明确说明。
- 根目录 `app-metadata.json` 是名称、版本、作者、邮箱及 GitHub 地址的唯一产品元信息来源；
  CMake、About、更新检测、安装器/发行信息及 README 受其约束，CI 检查双语元信息同步。
- Bug Report、Feature Request、Compatibility Report 和 PR 模板，中英 README 的联系、反馈和更新说明同步。

## 后续 Roadmap

自动回滚、多 ROS Bag 导入、多数据源对比转独立 PR，不阻塞此次发行。已验证功能保留。

## Release 清理顺序

1. 当前未验收阶段保留旧发行版，不提前删除，也不以计划日期触发正式发布。
2. v1.0.0 核心全部通过实际验收，正式资产、Release Notes、真实截图及已知限制齐全后发布。
3. 验证正式下载、安装/覆盖升级与核心运行成功后，按用户指令删除此前全部正式版、预发行版和草稿
   Release，仅保留 v1.0.0；保留 Git 提交历史及所有历史 Tags。

该条件式清理替代旧文档中长期保留回退 Release 的要求；当前条件尚未满足，不执行远端删除。
本文件描述验收要求，不能作为已实现或已测试的声明。
